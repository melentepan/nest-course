# Notification Service

Запуск: `npx nest start notification-service --watch`.

Socket.IO принимает access-токен User Service в `handshake.auth.token`.
После проверки подписи и срока действия соединение входит в `user:<sub>`.
Клиент не может выбрать комнату самостоятельно.

`POST /notifications/test` требует `Authorization: Bearer <accessToken>`.
Тело запроса не требуется. Роут отправляет фиксированное тестовое сообщение
только устройствам владельца токена. Ответ 204 означает завершение попытки
отправки, а не подтверждённую доставку или прочтение.

## Медленные клиенты

Уведомления доставляются только онлайн, без собственной очереди и повторов.
Перед отправкой проверяется готовность транспорта каждого сокета комнаты.
Если транспорт не готов к записи, сокет отключается. Для отправки используется
`volatile.emit`, чтобы не накапливать уведомления при недоступном транспорте.
Это строгая политика: даже временно занятое соединение может быть отключено,
а сообщение — потеряно. Клиенту нужно переподключиться. Истории пока нет.

Собственных таймеров и подписок на каждое соединение нет. При отключении
Socket.IO самостоятельно удаляет его из комнат. Проверка JWT выполняется
при подключении; истечение токена уже подключённый сокет не отключает.

Комнаты и поиск соединений используют локальный адаптер одного процесса.
Для нескольких экземпляров Notification Service понадобится общий адаптер
и согласованная политика доставки. Kafka на этом этапе не подключена.
