# Kafka и transactional outbox

## Запуск

1. `docker compose up -d` — запускает инфраструктуру. `kafka-init` создаёт топик
   `transfer.completed` с тремя partitions. Дождитесь успешного завершения
   kafka-init.
2. `npx nest start user-service --watch`.
3. `npx nest start notification-service --watch`.
4. Kafka UI: http://localhost:8080.

`KAFKA_BROKERS=localhost:9092` для приложений на хосте.
Для приложений в Docker-сети: `KAFKA_BROKERS=kafka:29092`.

Миграция CreateTransferOutbox1795176000000 автоматически применяется TypeORM
при старте User Service (migrationsRun). Создаётся только новая таблица и
индекс;
существующие балансы не меняются. Запись о выполнении хранится в таблице
migrations.
Не требуется включать synchronize. Для чистой базы схему пользователей нужно
подготовить отдельно — эта миграция добавочная, не baseline всего проекта.

## Путь события

BalanceRepository выполняет списание, зачисление и INSERT transfer_outbox
одним транзакционным EntityManager. Ошибка любого действия откатывает всё.
Публиковать в Kafka внутри транзакции перевода нельзя.

OutboxPublisher каждые 5 секунд обрабатывает до 100 записей, по одной в
транзакции.
SELECT FOR UPDATE SKIP LOCKED удерживает блокировку выбранной записи во время
отправки: второй экземпляр publisher пропустит её. Локальный running
предотвращает
перекрытие запусков в одном процессе. Блокируются строки outbox, не
пользователей.

После подтверждения Kafka выставляется published_at. Ошибка отправки увеличивает
attempts, откладывает повтор на 30 секунд и сбрасывает соединение producer.
После перезапуска процесс снова найдёт неопубликованные записи. published_at
обновляется отдельно от catch отправки: ошибка БД откатывает транзакцию
обработки.

eventId создаётся один раз в транзакции перевода и не меняется при повторах.
Возможно окно: Kafka приняла событие, а published_at ещё не записан. После сбоя
событие придёт повторно с тем же ID. Это at-least-once, не exactly-once.
Таймаут ожидания публикации также не доказывает, что брокер не принял сообщение.

Consumer использует одну группу transfer-notifications-v1 (Nest добавляет
-server),
читает существующие сообщения с начала при отсутствии сохранённого offset,
проверяет payload и пытается отправить notification обоим участникам.
Затем коммитит offset + 1. BigInt сохраняет точность больших offsets.
При ошибке выбрасывается KafkaRetriableException; offset не подтверждается.
Невалидное событие тоже блокирует partition повторными попытками: это осознанная
политика без молчаливого пропуска, для production нужна DLQ и мониторинг.

## Границы гарантий

Outbox гарантирует совместное сохранение перевода и намерения отправить событие.
Доставка Kafka повторяется при восстановлении брокера. Это не идемпотентность
HTTP-перевода: повтор POST может выполнить ещё один перевод.

Socket.IO остаётся онлайн-доставкой с volatile и отключением занятого
транспорта.
Offset означает обработку сервером, не прочтение пользователем.
Офлайн-пользователь
не получит историю. Клиент должен устранять повторы по eventId.

Порядок записей при нескольких publisher или отложенных повторах не
гарантирован.
Ключ fromUserId выбирает partition, но не исправляет порядок публикации outbox.

Notification Service рассчитан на один экземпляр: Kafka consumer group
распределит
сообщения между экземплярами, а локальные Socket.IO-комнаты не общие. Для
масштабирования потребуется общий Socket.IO adapter и изменение доставки в
gateway.

Локальный брокер один, replication-factor=1; acks=-1 подтверждает доступные
реплики,
но не даёт отказоустойчивость к потере единственного диска. Kafka хранит данные
в volume.
Опубликованные outbox-записи сохраняются; автоматическая очистка пока не
включена.

## Проверка вручную

Зарегистрируйте отправителя и получателя, задайте тестовый баланс отправителя.
Подключите их Socket.IO с access-токенами и слушателем notification.
POST /users/transfer должен дать обоим одинаковое событие с eventId и строковой
amount.
Недостаток средств не создаёт outbox-запись. При остановленной Kafka перевод
должен
завершиться, запись остаться с published_at=NULL. После запуска Kafka она
публикуется.
